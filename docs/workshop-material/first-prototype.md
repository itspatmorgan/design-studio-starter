Start with one question you want to explore. A small working flow gives you something concrete to review before you invest in more detail.

This walkthrough explores a checkout where customers can understand delivery costs before paying. Substitute your own idea at any step.

## Build a small flow

Ask your agent in the studio folder:

> Create a prototype called Checkout exploration for first-time customers. Use the existing Product system. Build a small flow through basket review, delivery, payment, and order confirmation. Make delivery costs clear before payment. Use sample data and simulated payment. Ask me about decisions that would materially change the experience.

Replace Product with a system available in your studio. If you are unsure which to use, ask the agent to help you choose.

The agent can create the prototype and its screens, called **views**. Ask it to show you where to open the result and explain any assumptions. You can also select **New prototype** in Studio to create the starting files, then ask the agent to build your flow there.

## Try the result

Open the prototype and act as a customer. Can you complete the flow? Are costs clear at the right moment? Can you go back and change a choice?

Tell the agent about anything that behaves differently from what you intended. A screen can look finished while important interactions still need work.

## Explore the states that matter

A **state** is a condition a screen can show, such as loading, success, or an error. Choose states that help answer your design question:

> Add an empty basket and a declined-payment state to Checkout exploration. Make each easy to open and review. Let the customer retry payment without losing their delivery choice. Explain which behavior is simulated.

Ask the agent how to reach each state. It can make separate views or demonstrate them within the flow, depending on the exploration.

## Request a revision

Describe the problem and what should stay:

> The delivery step feels too busy. Keep the total cost visible, simplify the choices, and explain the recommended option. Preserve the retry behavior we just added.

Try the revised flow again. If you want to compare directions, ask the agent to preserve the current version before exploring an alternative.

## Build the thinking around the screens

Your prototype can hold more than views. If the corresponding tools are enabled, continue with the artifact chapters: **Diagrams** map the checkout flow, **Documents** record notes and decisions, and **Canvases** arrange the work for comparison and annotation.

These are useful ways to explain an idea, not required steps for every prototype. Each artifact stays with the same exploration. If a tool is missing, ask your agent which capabilities are available.
