A prototype is a folder in your space, `src/prototypes/<you>/`. The app finds it automatically. You never have to register it anywhere.

## The shape of a prototype

```text
src/prototypes/patrick/hello-world/
├── meta.json        # title and description
├── prototype.tsx    # a view (opens first)
├── lofi/            # a group of views
│   └── main.tsx
└── components/      # helpers, not views
```

Always create a prototype with `pnpm new "Prototype Name"`, or by asking your agent for one. It sets everything up the same way every time.

While the app is running locally, the prototype's navigation shows all of its files and folders, and it updates as they change. Views open in the app. Other files, like `meta.json` or a component, open in your code editor. Right-click any file to reveal it in Finder or copy its path. On the deployed site, the navigation lists just the views.

In your own prototypes, the navigation works like a file browser:

- **New file or folder:** the buttons next to Files, or right-click a folder. A new `.tsx` file starts as a view and opens right away.
- **Rename:** right-click, or select a file and press F2.
- **Move:** drag a file or folder onto another folder, or onto the empty space below the list for the top level.
- **Delete:** right-click, or press Delete. It goes to the Trash, so you can put it back.

Each of these is an ordinary change to the files, the same as your agent would make, so you can mix both ways of working. If you rename or move the view you're looking at, the app follows it, and `start` in `meta.json` is updated to match.

## Views

A view is one screen of your prototype. Any `.tsx` file at the top level of the folder is a view, as long as it exports a React component. The prototype opens on `prototype.tsx`, unless `meta.json` says to start somewhere else.

## Groups

A subfolder is a group of views, shown under its name in the prototype's navigation. Groups are one level deep. Two folder names are special: `components/` holds helper components that aren't views, and `documents/` is set aside for a future feature.

A common group is `lofi/`: rough, grayscale sketches of an idea, before it's worth polishing.

## meta.json

```json
{
  "title": "Hello World",
  "description": "A first prototype.",
  "created": "2026-09-28",
  "system": "product",
  "start": "lofi/main"
}
```

Only `title` is required. `pnpm new` fills in `created`. Your name comes from `contributors.json`, so it isn't repeated here.

`system` is the [design system](/guide/systems) it builds with. Leave it out to use the default, which is all you need until your team has more than one.

`start` is the view the prototype opens on, written the way it appears in the URL. Leave it out to open on `prototype.tsx`. Change it whenever a different view becomes the one to show first, and the prototype's link still works.

If `meta.json` is missing or broken, the app skips the prototype with a warning, and the build fails until it's fixed.

## URLs

Every view has its own link, so you can share exactly what you mean:

| URL | Opens |
| --- | --- |
| `/patrick/hello-world` | The prototype's first view |
| `/patrick/hello-world/prototype` | A view |
| `/patrick/hello-world/lofi/main` | A view in a group |

## When a view breaks

If a view throws an error, the app shows the error with a Copy button, and everything else keeps working. Paste the error to your agent.
