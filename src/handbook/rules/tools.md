# Tools

A tool is a prototype the team has published as a small app to use: it makes something (an asset, a file, a setting) for whoever opens it. It is still a prototype folder, with views, and optionally a document or canvas beside it. What changes is where it lives and how it opens.

- **Draft**: a tool being built is an ordinary prototype in the person's folder, made with `pnpm new` like any other. Build it like any prototype.
- **Published**: **Publish as tool** (the prototype's … menu, or Publish a prototype on the Tools page) moves the folder to `src/tools/<id>/` and writes `"maintainers": ["<their key>"]` in `meta.json`. Its address changes from `/prototypes/<contributor>/<id>` to `/tools/<id>`. Links inside its own canvases and documents are rewritten; links from other prototypes are reported, and need fixing by hand. **Unpublish** moves it back.
- **Who may change it**: only the keys in `maintainers`. It is a list so more people can be added; add a key to give someone else access, and the scope check reads the list from before the change. Never edit `src/tools/<id>/` for someone who isn't a maintainer. Publishing and unpublishing move files out of and into the person's own folder, so they're in scope for the maintainer.
- **How it opens**: on the deployed site, `/tools/<id>` shows only the tool's start view, filling the window, with no rail or navigation. Choose the screen people land on with `start`, like any prototype. Other views can link to each other; every view in a tool opens full-window there. Locally the usual prototype navigation stays, so it can be edited.
- **Building one**: design the start view as an app, not a page in a gallery. It owns the whole window, so give it its own header and controls, and don't rely on the prototype navigation. What it outputs should be a download or a copy to the clipboard (PNG, SVG, CSS, JSON), never a file written into the repo. Settings that are worth sharing belong in the URL.
- Tools follow the same rules as prototypes otherwise: depend only on the tool's own folder, its design system, and `src/lib/`; helpers go in `_`-prefixed files and folders; `status` can archive one.
